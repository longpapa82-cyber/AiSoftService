# Hero 상단 고도화 — XP 게이지 확대 + 게이미피케이션 농도↑

**목표**: 현재 Hero를 "게임 그림"에서 "게임 화면"으로. XP 바를 두껍게 키워 RPG 경험치 바처럼 만들고, 배경에 부유 요소를 더해 재미와 깊이를 강화한다.

**확정된 방향** (사용자 선택)
- XP HUD 형태: **두꺼운 XP 게이지 바** (가로 막대 유지, 8px → 18~24px)
- 무드 강도: **현재 밝은 하이테크+골드 톤 유지 + 게이미피케이션 농도↑** (신규 팔레트 없음, `--ais-*` 토큰 정제·확장)
- 비주얼: **배경 파티클·플로팅 요소 강화** (이미지 에셋 0, CSS/SVG만)

**원칙**: 모션은 `transform`/`opacity`/`clip-path`만. 전부 `prefers-reduced-motion`에서 정지. 신규 라이브러리 0. 기존 자산(XP 카운트업 `useCountUp`, ONLINE 펄스, 레벨 칩, conic 테두리)은 유지·확장하고 중복 구현하지 않는다.

## 현재 진단 (첨부 이미지 + 코드 기준)

| 요소 | 현재 | 문제 |
|------|------|------|
| XP 바 | 높이 8px, 단색 골드 채움 + 시머 | 가늘어서 "진행선"처럼 보임. 게임 게이지의 무게감 없음 |
| XP 행 | `XP [바] 9,999` 한 줄 | 레벨/넥스트 정보 없이 숫자만. 맥락 빈약 |
| 레벨 배지 | LV.∞ // AI APP STUDIO + ONLINE | 평면 나열. HUD 위계 약함 |
| 배경 | aurora blob 3개 + 그리드 | 잔잔함. "플레이 공간" 긴장감 부족 |
| 우측/여백 | 중앙 단일 컬럼, 주변 비어있음 | 부유 요소 없어 정적 |

## Phase A — 두꺼운 XP 게이지 바 (핵심 ⭐)

XP 바를 RPG 경험치 바로 재설계. "세로 사이즈 키우기"가 사용자 1순위 요청.

- **A.1 높이 확대**: 8px → `clamp(18px, 2.2vw, 26px)`. 트랙 라운드/보더/내부 그림자(inset)로 "홈이 파인 게이지" 입체감.
- **A.2 세그먼트 눈금**: 채움 위에 `repeating-linear-gradient`로 세로 분절선(경험치 칸 느낌). 채움 끝에 "리딩 엣지" 하이라이트(밝은 캡).
- **A.3 라벨 구조 강화**: 단일 `9,999` → 좌측 `XP` 배지 + 바 + 우측 `9,999 / 10,000`(현재/다음 레벨). 바 위에 작은 `LV.∞ → MAX` 캡션.
- **A.4 시머 유지·강화**: 기존 `xpShimmer` 유지하되 두꺼워진 바에 맞춰 폭/속도 재튜닝. 채움 완료 시 끝에서 "팝" 1회(scale).
- **A.5 카운트업 연동**: 기존 `useCountUp`(0→9,999)에 바 채움 `scaleX`도 동기화(현재 CSS 독립 애니 → 카운트업 값과 일치시켜 숫자·바가 함께 참).

**파일**: `Hero.tsx`(라벨 구조), `Hero.module.css`(.xpRow/.xpTrack/.xpFill 전면), `tokens.css`(세그먼트/캡 토큰 1~2개).

## Phase B — HUD 위계 재구성 (레벨/상태 패널화)

평면 나열된 HUD 요소를 "게임 상태 패널"처럼 묶어 농도를 올린다.

- **B.1 레벨 배지 입체화**: LV.∞ 배지에 골드 그라디언트 채움 + 미세 베벨(inset highlight). 호버 시 살짝 회전/광택.
- **B.2 ONLINE 도트 강화**: 7px → 9px, 펄스 ring 2겹(현재 1겹). "LIVE" 톤 강조.
- **B.3 미니 스탯 칩 추가**: 레벨 행 옆에 `◈ 3 SERVICES` / `⚡ 100% UPTIME 아님 — 근거 있는 값만` → **데이터 도출 값만**(서비스 3개 등). 허위 수치 금지(표시광고법 준수, 기존 정책 유지).
- **B.4 XP 바와 레벨 배지 정렬**: 같은 max-width 컬럼으로 묶어 "HUD 블록"으로 인식되게.

**파일**: `Hero.tsx`, `Hero.module.css`.

---

## Phase C — 배경 파티클·플로팅 강화 (비주얼 ⭐)

에셋 없이 CSS/SVG로 "살아있는 플레이 공간". 사용자 선택 항목.

- **C.1 XP 오브 부유**: 골드/파스텔 작은 원형 빛 입자 6~10개가 `translateY`로 느리게 떠다님(서로 다른 속도·딜레이). `prefers-reduced-motion`에서 정지.
- **C.2 도트 그리드 패럴랙스**: 기존 `usePointerParallax`에 도트 레이어 1개 추가 — 마우스 따라 미세 이동(깊이감).
- **C.3 서비스 아이콘 위성**: 3개 서비스 아이콘(이미 자산 보유)을 히어로 주변에 작게 부유시켜 "수집 가능한 캐릭터"처럼. 호버 시 팝(이미 칩에 있는 모션 재사용).
- **C.4 스캔라인/그리드 글로우**: 배경 그리드에 느린 글로우 스윕 1줄(가로) — 하이테크 "스캐닝" 디테일.
- **C.5 코너 HUD 프레임**: 화면 모서리에 게임 UI 풍 코너 브래킷(`⌜ ⌝ ⌞ ⌟`) 미세 표시 — "게임 화면 안" 느낌. 절제해서.

**파일**: `Hero.tsx`(파티클·아이콘 위성 마크업), `Hero.module.css`, `usePointerParallax.ts`(레이어 추가 가능).

---

## Phase D — 마감 & 검증

- **D.1 reduced-motion 전수 점검**: 신규 파티클·오브·시머·팝 전부 정지 확인.
- **D.2 성능**: 파티클 개수 상한(≤10), `will-change` 좁게, 컴포지터 속성만 → LCP/INP 회귀 없음 확인.
- **D.3 반응형**: 두꺼운 XP 바·파티클이 320/375/768에서 깨지지 않게. 모바일에선 파티클 수 축소(또는 비표시).
- **D.4 접근성**: XP 바 `role="img"` + aria-label 갱신("경험치 9,999 / 다음 레벨까지"), 파티클·코너 전부 `aria-hidden`.
- **D.5 빌드 + 전/후 스크린샷**: `npm run build`, 데스크톱+모바일 캡처 비교.

## 검증 게이트 (각 Phase 후)
1. `npm run build` 통과
2. reduced-motion 시 신규 모션 전부 정지
3. 폰 실기기(`192.168.45.46:5173`) 320/375px 오버플로 없음
4. XP 카운트업 숫자 ↔ 바 채움 동기화 확인
5. 파티클로 인한 텍스트 가독성 저하 없음

## 구현 순서 제안
**A(두꺼운 XP 바) → B(HUD 위계) → C(파티클) → D(마감)**.
A가 사용자 1순위 요청이자 가장 체감 큰 항목 → 먼저 완성·확인 후 진행.
A·B는 같은 HUD 영역이라 연속 작업, C는 배경 레이어라 독립적, D는 마지막.

## 범위 밖 (YAGNI)
- localStorage 레벨 저장(본격 게임화) — 이전 결정대로 제외.
- 신규 이미지/3D 에셋·Lottie — 도입 안 함(CSS/SVG only).
- 우측 캐릭터 일러스트 2단 구성 — 이번엔 단일 컬럼 + 배경 파티클 방향 선택됨.
- 신규 색 팔레트 — 톤 유지.
- 근거 없는 수치(UPTIME 100% 등) — 표시광고법상 금지, 데이터 도출 값만.
